# NeoMundi Signal Adaptation Framework

Conceptual framework for adapting different data sources into normalized states measurable by NeoMundi.

---

## Repository purpose

This repository describes the role of an adaptation layer between a data source and the NeoMundi measurement engine.

NeoMundi does not directly measure “text”, “an image”, “a video” or “a financial market”.

NeoMundi measures a normalized state.

Text generated by an LLM is currently the first public application case. But the architectural principle is broader: any source capable of being transformed into a normalized state representation may, in theory, be evaluated through the same measurement framework.

This repository does not describe a complete implementation of a multimodal normalizer. It defines a conceptual boundary, an input contract and a research direction.

---

## General principle

A source produces a stream.

This stream is adapted by a dedicated layer.

This layer produces a canonical state.

NeoMundi measures this state.

The result is a runtime governance signal.

```text
Source
  ↓
Signal Adaptation Layer
  ↓
Canonical State
  ↓
NeoMundi Measurement Engine
  ↓
Runtime Governance Signal
```

---

## Why an adaptation layer?

Digital systems do not all produce the same type of output.

An LLM produces text.

A vision system produces images, embeddings, detected objects, trajectories or confidence maps.

An audio system produces time segments, frequencies, transcriptions or acoustic signatures.

An agentic system produces actions, tool calls, intermediate decisions and state transitions.

A financial system produces time series, risk signals, price streams or structured decisions.

To prevent the NeoMundi engine from depending on a single modality, an adaptation layer can convert these heterogeneous outputs into a comparable, measurable and interpretable state representation.

The normalizer is therefore not the product.

The product is the measurement applied to a normalized state.

---

## Separation of responsibilities

The adaptation layer prepares the state.

The NeoMundi engine measures the state.

The client system retains decision authority.

This separation is essential.

NeoMundi produces runtime governance signals and audit artifacts.

Decision authority remains with the client system, the configured policy or the responsible operator.

---

## Conceptual input contract

A normalized state representation should ideally include:

- an observable unit;
- a temporal or sequential window;
- measurable variables;
- a form of internal coherence;
- variation information;
- minimal traceability;
- an interpretation context.

Generic example:

```json
{
  "source_type": "llm | vision | audio | multimodal | agent | structured_system",
  "timestamp": "ISO-8601",
  "window_id": "string",
  "state_vector": {},
  "observables": {},
  "context": {},
  "trace": {}
}
```

This format is not a final standard. It serves as a conceptual basis for thinking about interoperability between sources, adapters and the measurement engine.

---

## Canonical State

The Canonical State refers to an intermediate representation that allows NeoMundi to measure a state without directly depending on the native format of the source.

It does not aim to reconstruct the full internal cognition of a system.

It also does not aim to prove the semantic truth of a content item.

Its purpose is to provide a representation that is stable, structured and observable enough to support runtime measurement.

---

## Current application case: language

In the case of an LLM, the source is a text generation.

The adaptation layer may organize this generation into observable windows, for example:

```text
tokens
  ↓
runtime windows
  ↓
coherence / stability / variation observables
  ↓
Canonical State
  ↓
NeoMundi Signal
```

This is the first public domain of application for NeoMundi because it can be directly tested on the outputs of current generative models.

---

## Conceptual extension: vision

In a vision system, the source may be an image, a video sequence, a segmentation map, an object detection output or a visual embedding.

A dedicated adaptation layer could transform these outputs into normalized observables:

```text
visual input
  ↓
detected structures / embeddings / confidence maps
  ↓
Canonical State
  ↓
NeoMundi Signal
```

This extension is conceptual at this stage. It does not constitute a claim of product availability.

---

## Conceptual extension: audio

In an audio system, the source may be an audio signal, a transcription, time segments, frequency variations or acoustic signatures.

An adaptation layer could produce a normalized representation of stability, continuity or rupture within the audio stream.

```text
audio stream
  ↓
segments / features / transcription / acoustic observables
  ↓
Canonical State
  ↓
NeoMundi Signal
```

This direction is exploratory.

---

## Conceptual extension: agentic systems

In an agentic system, the source is not only a final response.

It may include:

- tool calls;
- intermediate decisions;
- plan changes;
- trajectory errors;
- loops;
- escalations;
- transitions between states.

An agentic adaptation layer could convert these transitions into a measurable canonical state.

```text
agent actions
  ↓
tool calls / plans / state transitions
  ↓
Canonical State
  ↓
NeoMundi Signal
```

This case is particularly important for the governance of autonomous or semi-autonomous agents.

---

## Conceptual extension: financial or structured systems

In a financial or structured decision system, the source may be a time series, a risk score, an order sequence, an automated decision or a stream of signals.

An adaptation layer could represent these elements as a normalized sequential state.

```text
structured data stream
  ↓
risk variables / time windows / decision states
  ↓
Canonical State
  ↓
NeoMundi Signal
```

This extension must be handled carefully and requires sector-specific validation.

---

## What this repository does not claim

This repository does not claim that NeoMundi already measures all modalities in production.

It does not claim a universal proof of truth, safety, compliance or causality.

It does not claim that the adaptation layer replaces domain expertise.

It does not claim that a NeoMundi signal alone constitutes authorization, certification or regulatory proof.

It describes an extension architecture: source, adaptation, canonical state, measurement, signal.

---

## Scientific positioning

The NeoMundi engine is designed to be modality-agnostic, provided that a normalized state representation can be produced.

Text is the first public use case.

Other modalities require dedicated adaptation layers, specific validation protocols and clearly documented limitations.

This repository makes visible the separation between:

- source;
- adaptation;
- canonical state;
- measurement;
- interpretation;
- decision.

---

## Short formulation

NeoMundi does not depend on text.

NeoMundi depends on a normalized state.

The adaptation layer transforms a heterogeneous source into a canonical state.

The NeoMundi engine measures this state.

The client system retains decision authority.
